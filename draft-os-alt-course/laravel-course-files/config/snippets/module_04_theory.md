# Модуль 4: Установка ОС Альт — инсталлятор и профили

Теория по **инсталлятору**, способам запуска, **VNC-install**, выбору **ядра**, **профилям** пакетов и **разметке диска** в ОС «Альт». Для сравнения с другими отечественными дистрибутивами см. раздел про **Ред ОС** и **«Астра Линукс»**.

---

## 1. Способы запуска установщика

Прежде чем начать установку, нужно понять, **откуда** её запускать. В Альт Линукс есть три основных способа получить установщик.

**С физического носителя** — ISO-образ записывается на DVD или USB Flash и используется для загрузки. Образы доступны на [basealt.ru](https://www.basealt.ru) и [getalt.org](https://getalt.org). Большинство продуктов линейки доступны для свободного скачивания; исключение составляет **Альт СП** и образы для части архитектур (например, **Эльбрус**).

**Живая система (LiveCD)** — особый режим, при котором носитель содержит не только установщик, но и готовый к использованию образ ОС, запускаемый в памяти. Поддерживает сохранение сеансов. Полезен для знакомства с системой или диагностики **без** установки на диск.

**Загрузка по сети (PXE)** — установщик загружается по сети через механизм **PXE/BOOTP**, источник пакетов берётся по сети (**NFS/FTP/HTTP** и т.п.). В Альт Линукс это связано с экосистемой **ЦУС**, в частности с модулем **«Сервер сетевых установок»** (см. также модуль про ЦУС и сетевую установку).

---

## 2. Экран загрузки установщика и выбор режима

Когда система загружается с установочного носителя, появляется меню с вариантами загрузки — первая точка, где администратор принимает решения.

**Обычная установка** — стандартный режим: установщик с локальным управлением на консоли.

**VNC install** — установка с удалённым управлением по **VNC** (подробнее в разделе 3).

**Rescue LiveCD** — режим восстановления: небольшой образ ОС в памяти **без** изменения дисков. Для восстановления уже установленной, но повреждённой системы (загрузчик, конфиги). Подробнее: [altlinux.org/Rescue](https://www.altlinux.org/Rescue).

**Change Kernel Flavour (клавиша F5)** — выбор варианта ядра (подробнее в разделе 4).

## 3. Установка по VNC

Заметная особенность инсталлятора Альт Линукс — **управление процессом установки по VNC** прямо с экрана загрузчика, ещё до старта установленной системы.

### Как это работает

Параметры VNC передаются как **параметры ядра** при загрузке. В меню загрузчика клавиша **E** открывает редактирование параметров (можно задать пароль подключения); **F10** запускает загрузку с указанными параметрами.

Пароль по умолчанию часто задаётся как **`VNCPWD`** (уточняйте по документации вашего релиза). После старта установщик ждёт входящего VNC-подключения.

```bash
# Подключение с администраторской машины (пример: tigervnc)
vncviewer <ip-адрес устанавливаемого узла>
```

### Два режима VNC-подключения

| Режим | Описание | Со стороны клиента / сервера |
|--------|-----------|------------------------------|
| Клиент к узлу | Администратор подключается к устанавливаемому узлу, зная его **IP** и пароль | Классическая схема «я подключаюсь к серверу» |
| Узел к клиенту | Устанавливаемый узел **сам** инициирует подключение к VNC-клиенту на машине администратора — указывается **IP** принимающей стороны | Удобно, когда IP устанавливаемого узла **неизвестен** заранее или недоступен напрямую |

### Зачем на практике

VNC-install актуален там, где **физический доступ** к серверу затруднён: удалённые серверные комнаты, стойки в ЦОД **без** KVM, сценарии массовой установки на похожее железо. В **Ред ОС** и **«Астра Линукс»** аналогичный механизм **в том же виде** в инсталляторе обычно **не** выделяется как отдельная опция загрузчика — это отличие именно подхода Альт к установке «с колёс».

## 4. Выбор ядра (Change Kernel Flavour, F5)

При нажатии **F5** в меню загрузчика открывается выбор **варианта ядра**. Типичные варианты в линейке Альт:

- **std-def** — стандартное, стабильное ядро. Разумный выбор для большинства **серверных** конфигураций, где важна предсказуемость.
- **un-def** — более свежая ветка ядра с актуальными патчами. Полезно на **современном** железе: новые CPU, сетевые карты, NVMe, где старое ядро может не иметь нужных драйверов или исправлений.

### Почему это важно

В ряде других дистрибутивов (**Ubuntu**, **Ред ОС**) выбор **конкретной ветки ядра на экране установщика** не выделяется так явно: ставится предложенный по умолчанию образ, смена ядра чаще обсуждается **после** установки через пакетный менеджер. В Альт Линукс выбор **сразу в инсталляторе** экономит время на **нестандартном** железе.

После установки сменить или добавить ядро можно через **apt-get** и связанные пакеты `kernel-image-*`, а также через средства администрирования (в т.ч. модули **Alterator** / **ЦУС**, например **alterator-update-kernel**), в зависимости от политики организации.

```bash
# Просмотреть доступные пакеты ядер (пример)
apt-cache search '^kernel-image'

# Установить ядро ветки un-def (пример; имена пакетов уточняйте по репозиторию)
apt-get install kernel-image-un-def

# Специфичный для Альт сценарий обновления ядра (см. раздел 7)
update-kernel
```

## 5. Профили установки сервера

После загрузки установщика и настройки диска предлагается выбрать **профиль** — согласованный набор пакетов и ролей. Это отличается от схемы «минимальная система сначала, роли потом», характерной для части зарубежных установщиков: в **Альт Сервер** выбор **профиля** задаёт стартовый состав системы **сразу**.

Типичные профили (**Альт Сервер**; точные названия в интерфейсе — по вашему релизу):

| Профиль | Назначение |
|---------|------------|
| **Офисный сервер** | Серверные приложения (файлы, почта, веб и т.д.), в учебных материалах часто связан с **systemd-networkd** как сетевым контекстом профиля. |
| **Контроллер Альт Домена (Samba DC)** | Роль **контроллера домена** на базе **Samba** — аналог доменных сценариев в инфраструктуре на базе Альт. |
| **Домашний сервер** | Диагностика, графическая среда **MATE**, **NetworkManager** — сценарий «небольшой офис / лаборатория» с GUI. |
| **Минимальная установка** | Только базовая система; дальше администратор наращивает состав через **apt-get**. Максимальный контроль, но требует уверенности в пакетах. |

**Важно:** после выбора профиля состав пакетов **можно скорректировать до начала копирования файлов**: установщик показывает **группы пакетов**, которые можно включить или отключить. Имеет смысл явно пройтись по списку, если политика безопасности запрещает лишние сервисы или если вы **ужимаете** роль под конкретный хост.

## 6. Профили разбиения диска

Параллельно с профилем **пакетов** настраивается **разметка** диска.

### Автоматический профиль

Установщик сам предлагает схему в зависимости от размера диска, объёма **ОЗУ**, типа прошивки (**BIOS/UEFI**) и схемы (**MBR/GPT**). Упрощённая логика для **Альт Сервер** (ориентир для отчёта; детали — по экрану установщика):

| Раздел | Файловая система | Замечание |
|--------|------------------|-----------|
| `/` (корень) | ext4 | Обычно всегда |
| swap | — | Зависит от ОЗУ |
| `/boot/efi` (ESP) | FAT32, порядка 100–500 МБ | При **UEFI** |
| BIOS Boot Partition | — | При **BIOS + GPT**, без точки монтирования |
| `/var` | ext4 | Часто на больших дисках отдельно, чтобы **логи и данные приложений** не забивали корень |

### Ручной профиль

Полный контроль. Доступны в том числе:

- **Программный RAID** — уровни вроде **0, 1, 4/5/6, 10** (по возможностям установщика): разделы → массив → ФС на массиве.
- **LVM** — гибкое изменение томов без полной переразметки «с нуля».
- **LUKS** — шифрование раздела; для приложений том выглядит как обычный.
- **Подтома Btrfs** — снапшоты и гибкость в рамках одной ФС; альтернатива части сценариев с **LVM**.

**Замечание для администратора:** при **ручной** разметке **ESP** и **BIOS Boot** нужно создать **самостоятельно**, если они требуются схемой **UEFI**/**BIOS+GPT** — автоматический профиль делает это за вас. Забыть про них — типичная ошибка при первой ручной установке.

## 7. Обновление системы сразу после установки

После установки разумно сразу привести систему к актуальному состоянию в репозитории:

```bash
apt-get update           # индексы репозиториев
apt-get dist-upgrade     # обновление пакетов по политике dist-upgrade
update-kernel            # см. ниже — специфика Альт
apt-get clean            # очистка кэша скачанных пакетов
reboot                   # после смены ядра — для загрузки в новое ядро
```

### Про `update-kernel`

**`update-kernel`** — утилита, ориентированная на **линейку Альт**: она не сводится к одной команде «как `apt-get install` одного пакета ядра». В типичном использовании она подтягивает **актуальное ядро в текущей ветке** и **обновляет конфигурацию загрузчика** (в т.ч. **GRUB**), чтобы новое ядро оказалось в меню загрузки предсказуемо. Путать её только с **`apt-get upgrade`** без понимания загрузчика нельзя: после установки ядра **пакетами** всё равно нужно убедиться, что **загрузчик** и **initramfs** согласованы с политикой обновлений.

## 8. Сравнение с Ред ОС и «Астра Линукс» (инсталлятор и установка)

Таблица — **обобщение для учебного сравнения**; в конкретных мажорных версиях интерфейс может отличаться — сверяйтесь с документацией вендора.

| Особенность | Альт Линукс | Ред ОС | «Астра Линукс» |
|-------------|-------------|--------|----------------|
| Выбор **варианта ядра** на экране установщика (F5 / flavour) | **std-def** / **un-def** и др. прямо при загрузке | Обычно один предлагаемый образ ядра установки; дальнейшая смена — постфактум | Аналогично: фокус на поставляемом ядре, детали — по релизу |
| **VNC-install** из загрузчика | **Есть** (встроенный сценарий) | **Нет** в том же виде | **Нет** в том же виде |
| **Профили пакетов** при установке сервера | Профили **Альт Сервер** (офисный, DC, домашний, минимальный и др.) | Свои роли/наборы | Свои роли/наборы |
| Поддерживаемые **архитектуры** (ориентир) | Широкая линейка платформ (см. раздел 9) | **x86_64**, **aarch64** и др. по продукту | **x86_64**, **aarch64** и др. по продукту |

## 9. Архитектуры и образы

Продукты **BaseALT** рассчитаны не только на **x86_64**: в линейке встречаются сборки под разные платформы (в документации и на портале — актуальный список). Для темы **установки** важно: **образ установщика и набор пакетов** зависят от **архитектуры**; выбор **ядра** и параметров загрузки на **Эльбрус** и других не-x86 платформах **не копирует** «как на обычном ПК» без чтения release notes.

Часть продуктов (например, **Альт СП**) и отдельные архитектуры могут распространяться **не** как свободно скачиваемые ISO с публичной витрины — это вопрос **лицензии и договора**, а не только технический.

## 10. Ограничение сервера сетевых установок (ЦУС)

Для сценария **сетевой установки** через инфраструктуру **ЦУС** («Сервер сетевых установок») в учебных материалах фиксируется важное ограничение: сервер сетевых установок в типичной конфигурации ориентирован на **Legacy-загрузку** (BIOS/PXE-класс сценариев), а **установка EFI-систем через этот механизм может не поддерживаться** или требовать отдельной схемы. На экзамене и в отчёте это стоит **явно** связывать с выбором: **PXE vs локальный USB/ISO с UEFI**.

## 11. Итоговая схема: что выбирается на каком этапе

```
Загрузка с носителя
        │
        ├─ F5 → Выбор ядра (std-def / un-def)
        │
        ├─ VNC install → Удалённое управление установкой
        │
        └─ Обычная установка / Rescue
                │
                ├─ Профиль разбиения диска
                │     ├─ Автоматический
                │     └─ Ручной (RAID / LVM / LUKS / Btrfs)
                │
                └─ Профиль пакетов
                      ├─ Офисный сервер
                      ├─ Контроллер Альт Домена
                      ├─ Домашний сервер
                      └─ Минимальная установка
```
