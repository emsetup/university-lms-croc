# PAM: аутентификация и политика паролей в ОС Альт

Сравнение с РедОС и «Астра Линукс» — в контексте администрирования, без претензии на исчерпывающее описание всех редакций и сертифицированных профилей.

---

## 1. Что такое PAM и зачем он нужен

**PAM** (Pluggable Authentication Modules) — стандартный механизм аутентификации в Linux: администратор настраивает правила входа и смены пароля **централизованно**, не перекомпилируя приложения. Приложение (например, `login`, `sudo`, `sshd`) вызывает библиотеку PAM; дальше выполняется **цепочка модулей** согласно конфигурации в `/etc/pam.d/`.

Через PAM в типичной системе настраиваются в том числе:

- сложность и политика паролей;
- блокировка после неудачных попыток;
- ограничения по времени жизни пароля;
- подключение внешних методов (2FA, смарт-карты и т.д. — если предусмотрено модулями).

> **Идея модуля:** PAM — не «ещё один файрвол», а **точка политики доступа**, где дистрибутивы чаще всего расходятся в деталях реализации. В **Альт**, **РедОС** и **«Астра Линукс»** отличаются состав модулей, хранилище паролей и способ описания политики паролей.

---

## 2. Как устроен PAM: типы строк и управление

Когда пользователь вводит пароль (консоль, `sudo`, SSH и т.д.), приложение не проверяет пароль «само по себе» — оно передаёт управление **стеку PAM** для выбранного **сервиса** (имя файла в `/etc/pam.d/`, например `passwd`, `system-auth`).

### Четыре типа (класса) правил в стеке

| Тип        | Назначение |
|-----------|------------|
| **auth**    | Проверка подлинности (пароль, ключ, токен) |
| **account** | Ограничения учётной записи (срок действия пароля, блокировка и т.п.) |
| **password**| Правила **смены** пароля (сложность, история) |
| **session** | Окружение сессии (лимиты, монтирование, аудит и др.) |

### Формат строки

Упрощённо:

```text
тип   управление   модуль.so   [аргументы]
```

Поле **управление** задаёт, как интерпретировать результат модуля:

| Управление   | Смысл (упрощённо) |
|-------------|-------------------|
| **required**  | Модуль обязателен; при ошибке итог обычно «отказ», но стек может продолжиться |
| **requisite** | При ошибке — немедленный выход из стека (часто жёстче, чем `required`) |
| **sufficient**| Успех может завершить цепочку досрочно |
| **optional**  | Результат не обязателен для итога |

Точная семантика зависит от версии `libpam` и порядка модулей — в спорных случаях ориентируйтесь на документацию дистрибутива и на **фактическое поведение** после теста в непроизводственной среде.

## 3. Архитектура PAM в Альт Линукс

Альт наследует линию **Openwall**: отсюда **TCB** (раздельное хранение shadow по пользователям) и модуль политики паролей **`pam_passwdqc`** вместо типичного для RHEL-семейства **`pam_pwquality`**.

### 3.1. Хранилище паролей: `/etc/tcb` вместо единого `/etc/shadow`

В «классическом» Linux хэши часто лежат в **`/etc/shadow`** (доступ root). В Альт по умолчанию используется **TCB**: для каждого пользователя — свой каталог и файл `shadow`.

Пример структуры:

```text
/etc/tcb/
├── root/shadow
├── user1/shadow
└── user2/shadow
```

Права подбираются так, чтобы **владелец** мог выполнять операции со своим паролем в рамках модели безопасности (в т.ч. через группу **`auth`** и SGID — как описано в материалах курса). `/etc/shadow` в Альт **может существовать**, но **режим по умолчанию** — TCB.

> **Зачем:** снижается необходимость открывать суперпользователю полный `/etc/shadow` для сценария «пользователь меняет **свой** пароль».

### 3.2. `pam_tcb` вместо `pam_unix` для работы с TCB

Так как хранилище не классическое `shadow` одним файлом, для учётных записей в TCB используется **`pam_tcb.so`**, а не **`pam_unix.so`** (который ориентирован на классическую схему с `/etc/shadow`).

Краткое сопоставление (учебный уровень):

| Параметр | РедОС / «типичный» Linux | Альт Линукс |
|----------|--------------------------|-------------|
| Хранилище паролей | `/etc/shadow` | `/etc/tcb/<user>/shadow` |
| Модуль auth (типично) | `pam_unix.so` | `pam_tcb.so` |
| Политика паролей (часто) | `pam_pwquality.so` | `pam_passwdqc.so` |
| Конфиг политики | `/etc/security/pwquality.conf` или строка в PAM | `/etc/passwdqc.conf` |

### 3.3. Цепочка `include` и символические ссылки

В РедОС и «Астра» нередко встречается **один крупный файл**-шаблон (`password-auth`, `common-password` и т.п.). В Альт распространена **многоуровневая схема** через `include` и **симлинки**, чтобы переключать общую политику (например, на LDAP/Kerberos), **не правя каждый сервис по отдельности**.

Упрощённый пример для `passwd` (идея, не копируйте вслепую в прод):

```text
# /etc/pam.d/passwd — точка входа
auth     include  system-auth
account  include  system-auth
password include  system-auth
session  required pam_deny.so
```

`system-auth` часто является **символической ссылкой** (например, на `system-auth-local`), который подключает «локальные» и «общие» фрагменты. Фактическая цепочка с **`pam_tcb`** и **`pam_passwdqc`** обычно собирается в файлах вида **`system-auth-local-only`** — их и показывают в методичке.

> **Практическое правило:** не редактировать «точку входа» вслепую; разбирать **реальную** цепочку после `include` и симлинков (`ls -l`, последовательное чтение файлов).

## 4. Политика паролей: `pam_passwdqc` и `/etc/passwdqc.conf`

Модуль **`pam_passwdqc.so`** (Openwall) задаёт правила **смены** пароля. В Альт параметры обычно **централизованы** в **`/etc/passwdqc.conf`**, а не размазаны только по строкам PAM.

### 4.1. Пример содержимого (иллюстративно)

```text
min=disabled,24,11,8,7
max=72
passphrase=3
match=4
similar=deny
random=47
enforce=users
retry=3
```

### 4.2. Параметр `min` — классы символов

Параметр **`min`** задаёт **минимальную длину** в зависимости от **классов символов** в пароле (несколько полей через запятую — см. `man passwdqc.conf` на стенде).

Упрощённая логика «чем сложнее классы — тем короче может быть пароль» принципиально отличается от схемы «одно число `minlen` для всех», характерной для многих конфигов `pam_pwquality`.

### 4.3. Другие параметры (кратко)

- **`max`** — верхняя граница длины (в т.ч. защита от злоупотреблений).
- **`passphrase`** — требования к «фразовым» паролям.
- **`match`**, **`similar`** — ограничения на повтор подстрок и «похожесть» на старый пароль.
- **`enforce`** — кому строго применять политику (`users` vs `everyone` и т.д. — **важно для root**).
- **`retry`** — число попыток ввода нового пароля при интерактивной смене.

> **Важно:** `enforce=everyone` может запретить и **root** ставить «слабый» пароль — осознанно выбирайте политику под регламент организации.

## 5. Сравнение с РедОС и «Астра Линукс»

### 5.1. Сводная таблица (учебный уровень)

| Параметр | Альт | РедОС | «Астра Линукс» (пример 1.7) |
|----------|------|-------|------------------------------|
| Политика паролей | `pam_passwdqc`, `passwdqc.conf` | `pam_pwquality`, `pwquality.conf` / строка PAM | `pam_cracklib`, `common-password` |
| Хранилище | TCB (`/etc/tcb/...`) | `/etc/shadow` | `/etc/shadow` |
| Auth-модуль (типично) | `pam_tcb` | `pam_unix` | `pam_unix` |
| Конфигурация | цепочки `include` + симлинки | крупные шаблоны (`password-auth`) | `common-*` |
| Хэширование | настраивается (в т.ч. современные алгоритмы) | часто `yescrypt` | в примерах курса — **ГОСТ** (`gost12_512` и т.п.) |

### 5.2. РедОС — ориентация на `password-auth`

Типично видна связка **`pam_pwquality`** + **`pam_unix`**, параметры длины и сложности — в одной цепочке, понятной администратору RHEL/CentOS.

### 5.3. «Астра Линукс» — ГОСТ и мандатная модель

В учебных материалах акцентируются:

- **`pam_cracklib`** (менее гибкий, чем `pwquality` / `passwdqc`, в зависимости от задачи);
- использование **ГОСТ**-хэшей в строках `pam_unix` (требования регуляторики для сертифицированных поставок);
- влияние **Parsec** и аудита на общую модель безопасности (не сводится к одному файлу в `/etc/pam.d/`).

> **Почему это важно:** перенос привычек «как в РедОС» в Альт без проверки файлов PAM и хранилища паролей приводит к ошибкам в отчётах и на стенде (не тот файл, не тот модуль, «не работает passwd»).

## 6. Диагностика и осторожность при правках

### 6.1. Что смотреть в первую очередь (Альт)

```bash
# Цепочка для смены пароля
cat /etc/pam.d/passwd

# Куда указывает общий симлинк
ls -l /etc/pam.d/system-auth

# «Сердцевина» локальной цепочки (имя может отличаться — проверьте include)
cat /etc/pam.d/system-auth-local-only

# Политика passwdqc
cat /etc/passwdqc.conf
```

### 6.2. TCB

```bash
namei -om /etc/tcb/ИМЯ_ПОЛЬЗОВАТЕЛЯ/shadow
ls /etc/tcb/
ls -l /etc/shadow
```

### 6.3. Тест политики паролей

Интерактивно: `passwd` под тестовым пользователем и набор паролей, **ожидаемо** отклоняемых политикой (только в учебной среде).

### 6.4. Типичные ошибки

- Править **симлинк** `system-auth` как обычный файл «на месте» — изменения могут потеряться при обновлении пакета; разбирайте **реальные** цели ссылок и шаблоны пакетов.
- Ошибиться в пути **`config=/etc/passwdqc.conf`** в строке PAM.
- Подставить **`pam_unix`** там, где данные в **TCB** — цепочка не согласуется с хранилищем.

> **Критично:** не экспериментируйте с PAM в **единственной** сессии root на продакшене. Держите консоль/восстановление, снимок ВМ или иной **план отката**.

## 7. Итог для администратора Альт

- При миграции мышления с РедОС/Астры — **не искать** «тот же» файл в `/etc/pam.d/` без проверки: имена и уровни `include` отличаются.
- При интеграции с LDAP/Kerberos — понимать **общую** точку переключения (симлинки и `system-auth-*`), а не править десятки сервисов вслепую.
- При аудите — явно фиксировать: **TCB**, **`pam_tcb`**, **`pam_passwdqc`**, **`/etc/passwdqc.conf`**.
- Политика паролей в Альт **не сводится** к одному `minlen` как в типичном примере `pam_pwquality`.

**Короткая шпаргалка:**

| Вопрос | Альт | РедОС | «Астра» |
|--------|------|-------|---------|
| Где хэши? | `/etc/tcb/<user>/shadow` | `/etc/shadow` | `/etc/shadow` |
| Где политика паролей? | `/etc/passwdqc.conf` | `pwquality` / строка PAM | `pam_cracklib` / `common-password` |
| Как менять политику? | `passwdqc.conf` + проверка PAM | параметры `pam_pwquality` | параметры `pam_cracklib` |
| «Ядро» локальной цепочки | `system-auth-local-only` (типично) | `password-auth` | `common-password` |

**Главная мысль модуля:** связка **TCB + pam_tcb + pam_passwdqc + include/симлинки** — характерная для линии Openwall/Альт модель, которую нужно **сознательно отличать** от шаблонов РедОС и от гостовской специфики «Астры».
