## О чём эта инструкция

Раздел **Практика** соединяет **инструкцию для студента** (Markdown) и **изолированное окружение** (Docker-образ с `check.sh` и lab-daemon). Это ключевой отличительный элемент курса по ОС: не только прочитать, но сделать на живой системе в контейнере.

> **Зачем этот раздел:** текст без образа — пустая кнопка «Начать практику»; образ без понятного задания — студент не знает критериев сдачи. Редактор связывает педагогику и инфраструктуру в одном месте курса.

## Кому и когда нужно

Модератору — при создании лабораторной; тестировщику — при приёмке сценария. Сборка и тег образа — в **Docker** (модератор/админ). Открытие: **Модули** → **Практика** → `>`.

## Что вы делаете здесь и какой результат ожидать

Вы пишете **Задание**, привязываете образ (`os-alt-lab-m1:latest` и т.д.), при смене версии — **Заменить** или **Отвязать**. После сохранения и **собранного** образа обучающий запускает контейнер, выполняет шаги, сдаёт через автопроверку.

## Пошаговая работа

1. **Убедитесь, что образ есть в библиотеке** и в статусе **Собран** (статья «Библиотека Docker»).
2. **Откройте редактор практики** из списка разделов модуля.
3. **Вкладка «Содержимое»:** опишите цель, исходные данные, шаги, критерии сдачи; укажите ожидаемые команды и файлы. Скриншоты — кнопка **Картинка** ([инструкция](/docs/admin/media-images)).
4. **Docker-образ:** проверьте текущую привязку; при необходимости **Заменить** → выбор из библиотеки; **Отвязать** — только если временно отключаете лабу.
5. **Настройки раздела:** название на хабе, тип **Практика**, **Активен**.
6. **Сохраните**, прогоните **Тестовый стенд** из библиотеки Docker и **Просмотр** / **Запустить** из **Содержимое** курса.

## Частые вопросы

**Образ «Собран», но проверка падает.** Откройте **Статус образа** и лог сборки; на стенде выполните `check.sh` вручную через **Тестовый стенд**. Частая причина — несовпадение путей в задании и в скрипте.

**Можно ли один образ на несколько практик?** Да, библиотека показывает «Используется: N привязок»; следите, чтобы изменение образа не сломало другой модуль.

**Тестировщик не видит Docker в шапке.** Это норма — он правит задание и привязку в редакторе, сборку делает модератор.

> **Важно:** образ должен быть **собран** до публикации модуля с практикой — иначе обучающий получит ошибку запуска вместо учебного опыта.
