## О чём эта инструкция

Редактор **Теории** — место, где вы пишете учебный текст модуля в **Markdown**: заголовки, списки, код команд для «Альт», ссылки на basealt.ru. Качество теории задаёт темп потока: слишком длинный блок без структуры утомляет, слишком короткий — не готовит к тесту и практике.

> **Зачем этот раздел:** единый редактор в админке вместо правки файлов на диске даёт версионирование в БД, счётчик символов и предсказуемый рендер у обучающегося. Настройки раздела отделяют «как называется этап» от «что внутри текста».

## Кому и когда нужно

Модератору и тестировщику при наполнении или обновлении модуля. Открывается из **Модули** → строка **Теория** → `>`. Перед публикацией курса сверьте превью через **Содержимое** → **Просмотр**.

## Что вы делаете здесь и какой результат ожидать

Вы редактируете текст на вкладке **Содержимое**, при необходимости меняете название и активность на **Настройки раздела**, сохраняете. Обучающий после сохранения видит обновлённую теорию на этапе модуля (если раздел **Включён** и курс опубликован).

## Пошаговая работа

1. **Модули** → **Теория** → `>` — откроется модал редактора.
2. **Напишите материал** на вкладке **Содержимое**: структурируйте H2/H3, выделяйте команды через **Code**, давайте ссылки через **Link**. Для иллюстраций и скриншотов — кнопка с иконкой изображения **Картинка** ([картинки в материалах](/docs/admin/media-images)).
3. **Следите за счётчиком символов** — очень объёмные главы лучше дробить или выносить справочные таблицы в приложение модуля.
4. **Вкладка «Настройки раздела»:** название этапа на хабе, тип **Теория**, переключатель **Активен** (аналог **Включён** в списке модулей).
5. **Сохранить изменения** — запись в БД. **Отмена** закрывает без записи.
6. **Проверка:** **Содержимое** курса → колонка **Теория** → **Просмотр** — рендер как у студента.

## Элементы интерфейса

![Редактор теории](/images/docs/admin-theory-editor.png)

| Элемент | Зачем нужен | Как пользоваться | Что произойдёт |
|---------|-------------|------------------|----------------|
| Вкладка **Содержимое** | Основной текст | Редактирование Markdown | Обновление теории |
| **Настройки раздела** | Метаданные этапа | Название, тип, активность | Подпись на хабе модуля |
| **B** | Акценты | Выделить фрагмент | Жирный текст |
| *I* | Термины | Выделить фрагмент | Курсив |
| **H2**, **H3** | Структура | Заголовки разделов | Навигация по тексту |
| **Code** | Команды shell | Обрамить `apt-get` и т.д. | Моноширинный блок |
| **Link** | Внешние источники | URL документации | Кликабельная ссылка |
| **Картинка** | Иллюстрации | [Библиотека картинок](/docs/admin/media-images) | Markdown `![…](/media/…)` |
| **Сохранить изменения** | Фиксация | После правок | Запись в БД |
| **Отмена** | Откат сессии | Закрыть модал | Без сохранения |
| Счётчик символов | Контроль объёма | Смотреть внизу | Оценка нагрузки на чтение |

## Частые вопросы

**Markdown из Word вставляется криво.** Очистите форматирование или правьте в простом редакторе; списки и заголовки в Markdown должны быть явными (`-`, `##`).

**Сохранил, но студент видит старое.** Обновите страницу у обучающегося; проверьте, что раздел **Включён** и курс не в **Черновике** для этого потока.

**Нужен ли отдельный файл theory.md в репозитории?** На портале источник истины — БД курса; сниппеты из пакета контента импортируются при создании модуля, дальше правки в этом редакторе.

> **Подсказка:** пишите теорию с прицелом на следующий **Тест** — формулировки вопросов должны опираться на то, что реально прочитано в теории.
